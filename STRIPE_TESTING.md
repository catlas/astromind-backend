# Stripe: включване в тестов режим (ръководство за собственика)

Ключовете ги слагате САМО вие, в Render. Не ги пращайте в чат, не ги записвайте във файлове и не ги комитвайте.
Живите плащания са изключени, докато не сложите изрично `STRIPE_ALLOW_LIVE=1`: ключ `sk_live_…` без него не прави нищо.

## 1. Тестов режим (без истински пари)

1. В Stripe Dashboard включете **Test mode** (превключвател горе вдясно).
2. **Developers → API keys**: копирайте *Secret key* (`sk_test_…`).
3. **Developers → Webhooks → Add endpoint**:
   - URL: `https://astromind-api.onrender.com/billing/webhook`
   - събития: `checkout.session.completed`, `checkout.session.async_payment_succeeded`, `checkout.session.async_payment_failed`,
     `checkout.session.expired`, `charge.refunded`, `charge.dispute.created`
   - след създаването копирайте *Signing secret* (`whsec_…`).
4. В Render → `astromind-api` → **Environment** добавете:
   - `STRIPE_SECRET_KEY` = `sk_test_…`
   - `STRIPE_WEBHOOK_SECRET` = `whsec_…`
   - (по желание) `BALANCE_ENFORCED=1`, когато искате таксуването да започне; без него всичко остава безплатно.
5. След рестарта страницата „Баланс“ показва синя бележка „Тестов режим“, а `GET /billing/config` връща `"payments_mode": "test"`.

## 2. Какво да пробвате (всичко с тестова карта)

| Сценарий | Как | Очаквано |
| --- | --- | --- |
| Успешно плащане | карта `4242 4242 4242 4242`, бъдеща дата, произволен CVC | балансът нараства, ред „Зареждане“ в историята |
| Отказана карта | `4000 0000 0000 9995` | баланс без промяна, покупката остава „pending“ и изтича |
| Отказ от плащане | „Back“ на страницата на Stripe | `?status=cancel`, нищо не се добавя |
| Повторен webhook | Dashboard → събитието → *Resend* | втори път нищо не се добавя |
| Връщане на сума | Dashboard → плащането → *Refund* | кредитът се отнема пропорционално, само от внесените средства |
| Оспорване | карта `4000 0000 0000 0259` | кредитът се отнема, покупката е „disputed“ |
| Закъсняло плащане | метод със забавяне (напр. SEPA в тест) | кредит само след `async_payment_succeeded` |

Тестовете в `backend/tests/test_stripe_events.py` и `test_billing.py` проверяват същите последователности със подписани събития
(повторени, закъснели, неподредени, оспорени, неуспешни, едновременни) без мрежа. Истинска връзка със Stripe не е пробвана от мен.

## 3. Преминаване към живо (само след отделно ваше одобрение)

Преди това: юридическите текстове и данните на фирмата в „Общи условия“ са попълнени и проверени от юрист/счетоводител, тестовият
режим е минал успешно, а в Stripe има жив акаунт. Тогава в Render сменете ключовете с `sk_live_…` и новия `whsec_…` (за живия
endpoint) и добавете `STRIPE_ALLOW_LIVE=1`. Събитие с „livemode“, което не съвпада с режима на ключа, се отхвърля.
